# Automated AnimeVault builds & releases

AnimeVault builds installers automatically when `main` changes and when a
pull request targets `main`. The desktop/webOS workflow and Android APK
workflow can also be run manually from the Actions tab.

The in-app download page links can keep using GitHub's latest-release download
URL format:

```text
https://github.com/animevaultofficial/animevaultofficial.github.io/releases/latest/download/<asset-name>
```

## Triggers

`.github/workflows/electron-build.yml` runs on any of:

| Trigger                 | What it does                                                   |
| ----------------------- | -------------------------------------------------------------- |
| `push` to `main`        | Builds installers, creates/updates the `vX.Y.Z` tag and Release |
| `pull_request` to `main`| Builds installers and uploads them as PR artifacts (no release)|
| `workflow_dispatch`     | Manual run from the Actions tab                                |
## How the automation works

1. A commit is pushed to `main`, a PR targets `main`, or either workflow is run
   manually.
2. The `desktop` job builds Windows, macOS, and Linux installers in parallel;
   the `webos` job packages the matching LG webOS app as an IPK.
3. PR and manual runs upload Actions artifacts. A push to `main` publishes the
   desktop and webOS artifacts to a GitHub Release.
4. The separate Android workflow builds and signs the APK, then appends it to
   the same commit-tagged GitHub Release. The release jobs share a concurrency
   group so they do not upload assets at the same time.
5. The download page points at `/releases/latest/download/...`, so buttons
   automatically serve the newest successful release assets.

## Stable download assets

The download page expects these release asset names:

- `AnimeVault-Windows-x64.exe`
- `AnimeVault-macOS-arm64.dmg`
- `AnimeVault-Linux-x64.AppImage`
- `AnimeVault-Android.apk`

The workflow also uploads the extra artifacts generated by `electron-builder`,
including arm64 Windows installers, Intel macOS packages, Linux DEB files,
blockmaps, and platform update metadata files. Duplicate `builder-debug.yml`
files are omitted so every GitHub Release asset has a unique filename.

## LG webOS builds

The `webos` job in `.github/workflows/electron-build.yml` builds an IPK on
pushes to `main`, pull requests, and manual runs. It uses the same mobile app
entry and the same public build-time configuration as the Android TV APK,
including the mobile media-source API. Download `animevault-LG-webOS-IPK` from
the completed workflow run's Actions artifacts. The artifact is retained for
30 days. Successful pushes also attach the IPK to the matching GitHub Release.

The workflow reads `VITE_API_URL`, `VITE_NEON_AUTH_URL`,
`VITE_HCAPTCHA_SITEKEY`, `VITE_CLOUDINARY_CLOUD_NAME`,
`VITE_CLOUDINARY_UPLOAD_PRESET`, and `VITE_MEDIA_SOURCE_API` from the
`github-pages` environment or repository Actions secrets. The auth proxy URL
matches the other app build workflows. These `VITE_` values are included in
the client build; server credentials such as `DATABASE_URL` are not passed to
the TV apps.

## What gets built

- **Windows** — NSIS installers for x64 and arm64.
- **macOS** — unsigned DMG and ZIP builds for Intel and Apple Silicon.
- **Linux** — AppImage and DEB packages.
- **Android** — Capacitor release APK.
- **LG webOS** — webOS TV IPK using the same mobile app entry as Android.

## Desktop auto updates

The Electron app checks GitHub Releases when it launches. Release publishing
includes the `electron-builder` metadata files (`latest.yml`, `latest-mac.yml`,
and `latest-linux.yml`) so desktop auto-update delivery works out of the box.

## macOS signing note

This repository intentionally builds unsigned macOS artifacts when Apple
Developer ID credentials are not available. That avoids requiring an Apple
Developer account in CI, but it does not defeat or bypass Gatekeeper. Users may
still need to approve the unsigned app in macOS Privacy & Security settings.
For production distribution, add Apple signing and notarization secrets
instead of relying on unsigned builds.

## Local verification

To check the workflow file locally:

```bash
# 1. Make sure the YAML is well-formed
node -e "require('js-yaml').load(require('fs').readFileSync('.github/workflows/electron-build.yml','utf8'))"

# 2. Trigger a manual build (requires the `gh` CLI authenticated against the repo)
gh workflow run electron-build.yml --ref main
```
